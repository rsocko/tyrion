# Security Policy

## Supported versions

Tyrion does not publish versioned releases yet. Security fixes are applied to the
current `main` branch. Historical commits and unmerged branches are not supported.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in a public issue, pull request, discussion,
commit, log, or artifact.

GitHub private vulnerability reporting is unavailable while this user-owned repository
is private under its current plan. Contact the repository owner through an existing
private channel and provide only enough information to establish a secure follow-up
channel. Do not send credentials, private financial data, reusable session material,
internal service details, or machine-specific paths in the initial report.

After the repository becomes public, the owner must enable and API-verify GitHub
private vulnerability reporting before accepting public contributions. This policy
will then direct reporters to **Report a vulnerability** on the repository Security
tab.

Once a secure channel is established, include the affected revision, expected and
observed behavior, impact, and a minimal reproduction using invented data. The
maintainer will acknowledge the report, coordinate remediation and disclosure, and
credit the reporter if requested and appropriate. No response or remediation deadline
is promised for this single-maintainer project.

## Deployment status

Automated publication is intentionally disabled. See
[`docs/DEPLOYMENT-TRUST-BOUNDARY.md`](docs/DEPLOYMENT-TRUST-BOUNDARY.md) for the
evidence required before it can be enabled.
